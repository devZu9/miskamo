# Варианты реализации идей

Этот файл фиксирует различные варианты реализации ключевых механизмов проекта.
Для каждого варианта описаны плюсы, минусы и статус.

---

## 1. Внесение искажений в датасет

### Задача

Из MIDI → WAV с внесёнными погрешностями (дрифт высоты, джиттер тайминга,
битые ноты, вибрато, шум), имитирующими любительскую голосовую запись.

### Вариант A — искажения на уровне нот (выбран, реализован)

Каждая MIDI-нота проходит через FluidSynth (SF2, фортепиано), после чего
к каждой ноте применяются индивидуальные искажения:

- **Pitch drift** — случайное смещение MIDI-ноты в полутонах
- **Timing jitter** — случайный сдвиг start/end каждой ноты
- **Bad notes** — случайная замена ноты шумом (пропуск ноты + глобальный шум)
- **Vibrato** — глобальная частотная модуляция поверх всего аудио
- **Noise** — глобальный белый шум

Для каждой пары генерируется два WAV (MIDI не сохраняется):
- `NNN_clean.wav` — MIDI → FluidSynth (piano), без искажений (эталон)
- `NNN_corrupt.wav` — те же ноты через FluidSynth + понотные искажения

### Вариант B — искажения на уровне аудио (отклонён)

Весь MIDI → один WAV через FluidSynth, затем глобальные искажения
применяются ко всему аудиофайлу: pitch shift (через librosa), шум,
вибрато (модуляция высоты всего файла), рандомные вырезки.

**Статус:** отклонён в пользу варианта A.

## 2. Сравнение методов распознавания MIDI

### Miskam'o (текущий)

CREPE (через DDSP wrapper.get_f0) → frame-level F0 → группировка соседних
одинаковых питчей → MIDI.

**Плюсы:** Быстро, monophonic, предназначен для голоса.
**Минусы:** Примитивный `_f0_to_midi()` — нет детекции onset/offset,
нет velocity, нет изгибов высоты.

### Foundation-Music-Lab (Basic Pitch)

CQT → TensorFlow CNN (3 heads: onset, note, contour) → peak detection
+ energy tracking → MIDI.

**Плюсы:** Полифонический, точный onset/offset, velocity, pitch bends.
**Минусы:** Тяжёлый (TensorFlow), обучен на фортепиано, шумный на голосе.
